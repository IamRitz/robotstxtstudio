# Robots.txt Generator

> The canonical robots.txt **writer** in `src/features/generator/`. Transforms a
> [`GeneratorConfig`](./PRD.md#15-domain-models) into a [`RobotsFile`](./PARSER.md)
> AST and serialized text, then composes the Validator, Explainer, and Tester for a
> live preview. Pure domain logic — no React/Next. Companion: [`PRD.md`](./PRD.md).

## Pipeline

```
GeneratorConfig → buildRobotsFile() → RobotsFile AST → serialize() → robots.txt text
                                          ↓ (generatePreview)
                          Validator · Explainer · Tester → preview
```

`generatePreview(config)` returns `{ config, file, text, validation, explanation, samples }`
— everything Screen 3 needs from one call. **No other feature constructs robots.txt
text directly; call `serialize`.**

## GeneratorConfig

| Field | Meaning |
| --- | --- |
| `template?` | Starter preset (seeds the rest). |
| `crawlerPolicies` | `{ [crawlerId]: "allow" \| "block" }` — only `block` entries produce rules. |
| `disallowPaths` | Paths disallowed for the `User-agent: *` baseline. |
| `sitemapUrl?` | Absolute sitemap URL. |
| `crawlDelay?` | `Crawl-delay` seconds on the baseline group. |

Crawler ids resolve to user-agent tokens via the catalog (`src/config/crawlers.ts`,
20 crawlers); unknown ids are ignored.

## Generation model (semantics over mock-fidelity)

- Only **blocked** crawlers get explicit groups: one group per category (with a
  comment header) listing the user-agents + `Disallow: /`.
- **Allowed** crawlers get **no** group — they inherit the `User-agent: *` baseline
  (`Allow: /` + the disallow paths). Giving an allowed crawler its own `Allow: /`
  group would make it *bypass* the global path disallows, so we don't (this diverges
  intentionally from the Screen 3 mock's literal per-crawler `Allow:` lines).
- The baseline `*` group is always emitted and carries `Allow: /`, the disallow
  paths, and any `Crawl-delay`.
- `Sitemap` is appended at file level.

## Presets

Locked to the approved set (PRD §11 S3); `news`/`portfolio` are intentionally absent.
A preset is a per-**category** policy plus default disallow paths; `applyPreset`
expands it to a full config (a policy for every catalog crawler).

| Preset | AI training | AI search | Search / SEO / Social / Data | Disallow paths |
| --- | --- | --- | --- | --- |
| **Blog** | block | block | allow / allow / allow / block | `/wp-admin/` |
| **SaaS** | block | block | allow / allow / allow / block | `/app/ /dashboard/ /api/ /admin/` |
| **E-commerce** | block | **allow** | allow / allow / allow / block | `/cart/ /checkout/ /account/ /admin/` |
| **Publisher** | block | **allow** | allow / allow / allow / block | `/wp-admin/ /drafts/` |
| **Documentation** | block | **allow** | allow / allow / allow / block | — |

## Serializer behavior

`serialize(file)` renders the AST's lossless `directives` backbone
(`raws.join("\n")`). The `LineWriter` in `build.ts` is the single formatter — it emits
raw lines while building the structured `groups`/`sitemaps`, so text and AST never
diverge. Deterministic: same config ⇒ identical output. No trailing newline.

## Round-trip guarantees

Because the writer emits exactly the lines the parser reads:

```
parseRobots(serialize(buildRobotsFile(config))) deepEquals buildRobotsFile(config)
```

Tests assert full AST equality (`toEqual`) for every preset and a custom config, plus
serializer idempotency and `validateRobots(file).isValid === true`. This makes the
parser the verification oracle for the writer (acceptance criterion).

## Architecture

```
src/config/crawlers.ts          # catalog (20 crawlers) + category order/labels
src/features/generator/
  domain/
    presets.ts    # PRESETS, applyPreset(), TEMPLATE_LABELS
    build.ts      # LineWriter + buildRobotsFile() — the canonical writer
    serialize.ts  # serialize(file) — AST → text
    generate.ts   # generateRobots() + generatePreview() (Validator/Explainer/Tester)
  index.ts        # barrel
```

## Testing

`src/features/generator/domain/*.test.ts` + `src/config/crawlers.test.ts` — catalog
validation, all presets, AI/custom/edge scenarios, round-trip fidelity, and preview
integration. Coverage ~99% of `generator/domain`.
